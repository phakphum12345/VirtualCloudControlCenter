PHakphum AI System Assistant - Full Specification
============================

Project Name:
Phakphum AI System Assistant

Application ID:
com.phakphum.aiassistant

Project Type:
Cross-platform AI system assistant and screen recorder

Supported Platforms:
- Windows
- macOS
- Linux
- Android
- iOS / iPadOS
- Web / ChromeOS

Main Goal:
Create one AI assistant application that can receive Thai or English commands
and help users manage screen recording, applications, files, device settings,
system diagnostics, and common troubleshooting tasks.

IMPORTANT PLATFORM LIMITATION:
Each operating system provides different permissions. The application must never
claim that a command succeeded unless the native platform adapter confirms it.

======================================================================
1. MAIN FEATURES
======================================================================

1. AI Command Center
- Accept text commands in Thai and English.
- Accept voice commands.
- Convert natural language into structured actions.
- Show the planned actions before important changes.
- Report the real result of every action.
- Support command history.
- Support emergency stop.

Examples:

- Open Visual Studio Code.
- Open my Flutter project.
- Reduce volume to 30 percent.

- Display a visible recording indicator.
- Save recording history.
- Open the output folder.

3. Application Manager
- Find installed applications.
- Open applications.
- Close applications after confirmation.
- Detect unresponsive applications.
- Show CPU and memory use.
- Restart an application after confirmation.
- Open an application location when supported.
- Open uninstall or application settings pages.

4. System Settings Assistant
- Open relevant settings pages.
- Control volume where permitted.
- Control screen brightness where permitted.
- Open Wi-Fi settings.
- Open Bluetooth settings.
- Open microphone settings.
- Open camera settings.
- Open display settings.
- Open storage settings.
- Open battery settings.
- Open notification settings.
- Change theme where permitted.

5. File Manager
- Search files and folders.
- Create folders.
- Rename files.
- Copy files.
- Move files.
- Open file locations.
- Find large files.
- Find duplicate files.
- Compress and extract ZIP files.
- Organize recordings and screenshots.
- Move deleted files to the recycle bin or trash where possible.
- Require confirmation before permanent deletion.

6. System Diagnostics
- Show CPU usage.
- Show memory usage.
- Show disk usage.
- Show battery information.
- Show active processes.
- Test network connectivity.
- Detect low disk space.
- Detect common application failures.
- Read user-approved logs.
- Suggest safe troubleshooting actions.

7. AI Safety and Permission Center
- Safe actions can run immediately.
- Important system changes require confirmation.
- High-risk actions require explicit confirmation.
- Dangerous commands must be blocked.
- All actions must be written to an activity log.
- The user must be able to stop the AI immediately.

======================================================================
2. PERMISSION LEVELS
======================================================================

SAFE:
- Open an application.
- Open a settings page.
- Search files.
- Read system status.
- Take a screenshot after permission.

CONFIRMATION REQUIRED:
- Close an application.
- Change system settings.
- Move many files.
- Start screen recording.
- Restart an application.
- Install or uninstall software.
- Restart or shut down the device.

RESTRICTED:
- Permanently delete files without confirmation.
- Disable antivirus or firewall protection.
- Bypass operating system permission prompts.
- Record the screen, camera, or microphone secretly.
- Read private application data without permission.
- Send files or personal data without confirmation.
- Run unrestricted AI-generated shell commands.
- Perform payments or financial transactions.

4. PLATFORM ADAPTERS
======================================================================

Windows Adapter:
- Windows Graphics Capture
- Windows audio APIs
- Windows process APIs
- Windows settings URI
- PowerShell commands from an allowlist only

macOS Adapter:

- NSWorkspace

Linux Adapter:
- XDG Desktop Portal
- PipeWire
- D-Bus
- X11 fallback where necessary
- Desktop-specific settings adapters

Android Adapter:
- MediaProjection
- Foreground Service
- Storage Access Framework
- Android intents
- Accessibility features only when explicitly enabled and appropriate

iOS / iPadOS Adapter:
- ReplayKit
- App-scoped file access
- Document picker
- URL schemes and universal links
- No unrestricted control of other applications

Web Adapter:
- Browser Screen Capture API
- MediaRecorder
- File System Access API where available
- Browser sandbox restrictions
- No direct control of desktop applications or system settings

11. AD AND TRACKER BLOCKING
======================================================================

Goal:
Add an optional privacy module that can reduce advertisements, tracking scripts,
pop-ups, autoplay media, and known malicious domains inside supported application
views and websites.

Supported blocking modes:

1. In-App UI Blocking
- The application's own user interface must not display third-party advertisements.
- Disable promotional banners, sponsored cards, and tracking SDKs by default.
- Allow the user to hide optional recommendation panels.
- Keep core controls visible even when ad filtering is active.

2. Embedded Browser / WebView Blocking
- Block requests matching approved filter lists.
- Block known advertising and tracking domains.
- Hide common advertisement containers using cosmetic filtering.
- Block pop-ups and automatic redirects.
- Block autoplay media when enabled by the user.
- Allow per-site exceptions.
- Show the number of blocked requests.
- Provide a temporary disable button for websites that stop working.

3. Website Blocking
- Web builds may filter requests only inside the application's own pages and
  supported browser contexts.
- A browser extension may be provided for supported desktop browsers.
- A local DNS or proxy mode may be offered on platforms that permit it.
- The user must explicitly enable system-wide filtering.
- HTTPS traffic must not be decrypted or inspected by default.

4. DNS-Level Filtering
- Block known advertisement, tracking, phishing, and malware domains.
- Support custom allowlists and blocklists.
- Support family-safe and privacy-focused profiles.
- Show which domain was blocked and why.
- Allow the user to disable DNS filtering immediately.

5. Filter List Management
- Built-in safe default list.
- Optional community filter lists.
- Automatic list updates.
- Manual update button.
- Custom rules.
- Site allowlist.
- Rule validation before activation.
- Restore default rules.

Example commands:
- Block ads on this website.
- Disable pop-ups.
- Allow ads on this site.
- Turn on privacy protection.
- Show what was blocked.
- Disable ad blocking for ten minutes.
- Add this domain to the allowlist.
- Update the filter lists.

Standard action example:

{
  "id": "cmd_20260727_002",
  "action": "content_filter.enable",
  "parameters": {
    "scope": "webview",
    "blockAds": true,
    "blockTrackers": true,
    "blockPopups": true,
    "blockAutoplay": false,
    "site": "current"
  },
  "risk": "safe",
  "requiresConfirmation": false
}

Security and privacy requirements:
- Do not inject advertisements into the application.
- Do not sell browsing data.
- Do not upload browsing history without explicit permission.
- Do not intercept passwords, payment pages, or private messages.
- Do not install a root certificate for HTTPS interception by default.
- Do not block security updates or essential operating-system services.
- Clearly identify which filtering mode is active.
- Make it easy to pause or disable filtering.
- Keep filtering logs on the device unless the user chooses to export them.
- Treat banking, payment, health, and government websites conservatively.
- Provide a one-click emergency disable option.

Platform limitations:
- Windows, macOS, and Linux can support browser-extension, DNS, proxy, or
  application-level filtering depending on user permission.
- Android can support WebView filtering, private DNS guidance, or a local VPN
  filter after explicit user permission.
- iOS and iPadOS can support Safari content blockers, app WebView filtering, or
  approved network extensions; unrestricted filtering of every application is
  not available.
- Web applications cannot block advertisements across unrelated browser tabs or
  other websites without a browser extension.
- Advertisements drawn directly into video streams or server-rendered content
  may not be removable without breaking the content.

Recommended UI:

- Trackers blocked counter.
- Pop-up blocking switch.
- Autoplay blocking switch.
- Current site allow button.
- Filter list update status.
- Custom rules page.
- Activity log.
- Pause protection button.

======================================================================
10. DEFINITION OF DONE
======================================================================

The first complete version is ready when:
- The same Flutter interface runs on all target platforms.
- The application reports available capabilities correctly.
- Screen recording works on supported platforms.
- Every important action passes through permission checks.
- Unsupported commands return an honest explanation.
- Activity logs are saved locally.
- Emergency stop works immediately.
- No screen, camera, or microphone recording can run secretly.
- Native adapters return real success or failure results.
